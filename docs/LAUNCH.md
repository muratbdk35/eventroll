# Launch runbook

Going from the test site (eventroll-test.vercel.app, Neon branch `dev`, Stripe
test mode) to production on **eventroll.eu**. Work top to bottom; each step
says who does it. Keys and secrets never go into a chat: they go into one
local file that `scripts/launch-env.mjs` pushes to Vercel without printing.

## 0. Before the day

| What                                             | Who   |
| ------------------------------------------------ | ----- |
| Tax adviser confirmed: flat 19% VAT (no OSS yet) | Owner |
| Vercel Pro plan (commercial use)                 | Owner |

## 1. Accounts and keys (owner, ~30 min)

Write each value into `~/eventroll/.env.production.launch` (one `KEY=value`
per line; the file is git-ignored by its `.env` prefix). Values not listed
here are generated by the script.

| Variable                                                 | Where it comes from                                                                                                                                                                                                      |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NEXT_PUBLIC_APP_URL`, `BETTER_AUTH_URL`                 | `https://eventroll.eu`                                                                                                                                                                                                   |
| `NEXT_PUBLIC_APP_NAME`                                   | `EventRoll`                                                                                                                                                                                                              |
| `DATABASE_URL`                                           | Neon → project eventroll → branch **production** → Connect (pooled)                                                                                                                                                      |
| `R2_*` (5 values)                                        | Cloudflare → R2 → a **new bucket** `eventroll-prod` (EU jurisdiction) → API token with read/write on that bucket only                                                                                                    |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` | Cloudflare → Turnstile → the widget (or a new one) with hostname `eventroll.eu`                                                                                                                                          |
| `RESEND_API_KEY`, `EMAIL_FROM`                           | Resend → a production API key; `EventRoll <hello@eventroll.eu>` (domain already verified)                                                                                                                                |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`               | Google Cloud → the OAuth client (see step 4)                                                                                                                                                                             |
| `STRIPE_SECRET_KEY`                                      | Stripe → **live** mode → Developers → API keys → restricted key, same permissions as test (Products, Prices, Checkout Sessions, Charges and Refunds, Webhook Endpoints, Tax Rates: write; Payment Intents, Events: read) |
| `STRIPE_WEBHOOK_SECRET`                                  | Created in step 3; leave empty until then                                                                                                                                                                                |

Already in Vercel Production: `SUPPORT_EMAIL`, `UPSTASH_REDIS_REST_URL`,
`UPSTASH_REDIS_REST_TOKEN`, `SIGHTENGINE_API_USER`, `SIGHTENGINE_API_SECRET`
(new secret, 2026-10-19).

## 2. Database (Claude, ~5 min)

```sh
DATABASE_URL="<production pooled URL>" npx drizzle-kit migrate
```

All migrations (0000–0013) on the empty `production` branch. Check: the
tables exist and are empty. No test data is copied.

## 3. Stripe live (Claude, ~5 min)

```sh
STRIPE_SECRET_KEY=rk_live_… npm run stripe:setup   # products + 19% VAT rate
```

Then create the live webhook endpoint `https://eventroll.eu/api/stripe/webhook`
with the events `checkout.session.completed`,
`checkout.session.async_payment_succeeded`,
`checkout.session.async_payment_failed`, `checkout.session.expired`,
`charge.refunded` (via the API, as for the test site) and put its signing
secret into the file as `STRIPE_WEBHOOK_SECRET`.

In the Stripe dashboard (owner): Public details → website
`https://eventroll.eu`, privacy URL `https://eventroll.eu/en/legal/privacy`,
support email `hello@eventroll.eu`; product description "EventRoll: online
service for collecting guest photos at events, one-time payment per event".

## 4. Consoles (owner, ~10 min)

- **R2 CORS** on `eventroll-prod`: origin `https://eventroll.eu`, methods
  `PUT, GET, HEAD`, headers `content-type, content-length`.
- **Turnstile**: hostname `eventroll.eu` on the widget.
- **Google OAuth**: authorised origin `https://eventroll.eu`, redirect
  `https://eventroll.eu/api/auth/callback/google`; then "Publish app".
- **Neon**: point-in-time restore of at least 7 days (paid plan) if wanted.

## 5. Environment and deploy (Claude, ~10 min)

```sh
node scripts/launch-env.mjs ~/eventroll/.env.production.launch --dry   # check
node scripts/launch-env.mjs ~/eventroll/.env.production.launch
rm ~/eventroll/.env.production.launch
npx vercel deploy --prod
```

The app refuses to start in production when a required variable is missing
(`requiredInProduction` in `lib/env.ts`), so a failed build here means a
missing value, not a broken app.

## 6. Domain (owner + Claude, ~10 min)

- Vercel → project → Domains → add `eventroll.eu` and `www.eventroll.eu`
  (redirect www → apex).
- Cloudflare DNS: the records Vercel shows, **DNS only** (grey cloud), so
  Vercel issues the certificate and its edge stays in front.
- Wait until Vercel shows "Valid configuration" and HTTPS works.

## 7. Smoke test (Claude + owner, ~20 min)

1. `https://eventroll.eu` in tr/en/de; legal pages and contact form.
2. Sign in with an email code and with Google.
3. Create an event, buy **Mini with a real card**, publish.
4. On a phone: guest page, upload two photos, one RAW if at hand.
5. Dashboard: photos, download, save to gallery.
6. The buyer's email: invoice and receipt arrive; the invoice says "Paid".
7. Refund it in one click; refund email arrives; Stripe shows Refunded.
8. Cron: `curl -H "Authorization: Bearer $CRON_SECRET" "https://eventroll.eu/api/cron/daily?dry=1"` answers `dryRun: true`.
9. Contact form message reaches hello@eventroll.eu.
10. `/de/withdraw`: a test withdrawal reaches hello@eventroll.eu and the acknowledgement arrives.

## 8. After launch

- Legal texts checked by a lawyer or a legal-text service (questions: the
  withdrawal instructions and checkout consent, digital service vs digital
  content, the refund after the event has started); Claude applies the changes.
- Stripe Public details and the company site point at eventroll.eu.
- The test site stays on Preview for further work; it keeps test keys.
- CSAM hash scanning: Cloudflare's CSAM Scanning Tool needs photos served
  through a zone's cache, i.e. a media subdomain with a Worker checking our
  signed links (DECISIONS #57). Plan it right after launch.
- Watch the first week: Vercel logs, Sentry (if `NEXT_PUBLIC_SENTRY_DSN` is
  set), Stripe disputes, Sightengine usage against its plan.
